# Security policy

Gareji Board coordinates local agent work but must not become an arbitrary remote shell. Public, destructive, secret-bearing, or production-changing actions require explicit human approval.

Do not open a public issue containing credentials, personal workspace paths, private notes, customer data, raw transcripts, full diffs, or execution sidecars. Use GitHub private vulnerability reporting when enabled, or an already established private maintainer channel.

Until a public release policy is published, only the current private development revision is maintained.
